# Music Timeline

A self-hosted Hitster-style guessing game. Scan the QR on the back of a card with your phone — the app plays the song (audio only, no metadata leak) until someone reveals the year. The "game" itself is physical: place the card on your shared timeline.

The repo includes:

| Component | What it does |
| --- | --- |
| `data/songs.json` | ~495 curated songs: artist, title, year, region. YouTube IDs are filled in by the verifier — never hardcoded. |
| `scripts/verify.py` | Searches YouTube via yt-dlp, captures a real video ID per song, sanity-checks duration. Idempotent. |
| `scripts/build_songs.py` | Regenerates `songs.json` from the curated tuple list while preserving prior verification data. |
| `scripts/make_cards.py` | Generates a printable PDF: 3×3 cards per A4 sheet, fronts with QR, backs with the answer, mirrored for duplex printing. |
| `app/` | Cross-platform PWA: QR scanner + hidden YouTube player + reveal. Works on iOS and Android via the browser, installable to home screen. |

## Setup

```powershell

```

## Pipeline

### 1. Verify songs (find real YouTube IDs)

```powershell
python scripts/verify.py                  # verify everything not yet verified
python scripts/verify.py --limit 20       # smoke-test the first 20
python scripts/verify.py --ids w017,r130  # verify specific IDs
python scripts/verify.py --only-failed    # retry past failures
python scripts/verify.py --reverify       # re-check everything
```

The verifier:
- searches YouTube with `Artist Title` (no "official audio" — hurts older / non-English tracks)
- pulls the top 5 candidates and picks the first one with a plausible duration (45s..720s)
- writes results back to `data/songs.json` incrementally (every 10 songs) so long runs survive interruption
- failures are logged to `data/verify_failures.json` — retryable with `--only-failed`

### 2. Generate cards

```powershell
# Use this when the PWA is hosted somewhere — QR codes encode a URL the
# phone's native camera can open directly.
python scripts/make_cards.py --host https://your-host/app/

# Subset by id
python scripts/make_cards.py --ids w006,r130,i004 --host https://your-host/app/

# Only print cards that have a verified YouTube link
python scripts/make_cards.py --only-verified --host https://your-host/app/
```

PDF lands in `cards/`. Print double-sided (long-edge flip). The back sheet is column-mirrored so QR fronts and answer backs line up.

### 3. Host the PWA

#### GitHub Pages (already wired up)

`.github/workflows/pages.yml` deploys the whole repo to Pages on every push to `main`/`master`. To activate:

```powershell
# Using the GitHub CLI (gh) — easiest:
gh repo create music_timeline --public --source=. --remote=origin --push

# Or if you'd rather create the repo in the GitHub UI first, then:
git remote add origin git@github.com:<you>/music_timeline.git
git push -u origin HEAD
```

Then in the repo's **Settings → Pages**, set **Source** = "GitHub Actions". The first push kicks off a deploy; the URL appears in the Actions tab and at the top of Settings → Pages once it's live, e.g. `https://<you>.github.io/music_timeline/`.

The root URL redirects to `app/`, so `https://<you>.github.io/music_timeline/` opens the PWA directly. QR codes generated by `make_cards.py --host https://<you>.github.io/music_timeline/` will deep-link to a specific song.

#### Other static hosts

- **Netlify / Vercel / Cloudflare Pages**: point them at this repo, build command empty, publish dir `.` (or `/`). Same idea — they need to serve both `app/` and `data/songs.json`.
- **Local LAN testing**: `python -m http.server 8000` from the repo root, then open `http://localhost:8000/` on a desktop. Phones over LAN won't get camera permission because there's no HTTPS — the **game mode** still works (no camera needed), only the scanner fails. Use `ngrok http 8000` or Cloudflare Tunnel to expose with HTTPS for proper phone testing.

Phones require HTTPS for the camera scanner. All the hosted options above give it for free; localhost is the only HTTP exception browsers honour.

### 4. Play

1. Open the PWA on a phone. "Add to Home Screen" if you want it to feel like an app.
2. Tap **Scan a card** — the camera reads the QR.
3. The song starts playing immediately. No artist, no title, no thumbnail — just a spinning vinyl placeholder.
4. Place the card on the table relative to your existing timeline (left = older, right = newer).
5. Tap **Reveal answer**. If you got the relative order right, you keep the card.

## QR payload

QR codes encode one of:

- `https://your-host/app/?id=w017` — opens directly in the PWA via deep-link. Works with the phone's native camera app.
- `mt:w017` — short form, works only inside the in-app scanner.

Choose by passing or omitting `--host` to `make_cards.py`.

## Editing the song list

`data/songs.json` is the runtime database, but it's regenerated from `scripts/build_songs.py` (which holds the canonical tuple list). To add/remove/edit songs:

1. Edit the `SONGS` list in `scripts/build_songs.py`.
2. Run `python scripts/build_songs.py` — preserves verification data on rows whose `(artist, title, year)` hasn't changed.
3. Run `python scripts/verify.py` to fill in YouTube IDs for new rows.

## Troubleshooting

- **Cyrillic / Hebrew show as boxes on the printed cards**: the script looks for Arial, DejaVu Sans, or Noto Sans on common system paths. Install one and rerun.
- **`yt-dlp` returns "video unavailable"**: the script already tries up to 5 candidates per song. If all fail, the failure is logged. Re-run with `--only-failed` once or twice — transient.
- **Camera permission denied on the phone**: HTTPS is required. The local `http.server` approach only works on `localhost`, which won't help you on a phone. Use a tunnel like `ngrok` or push to GitHub Pages.
- **Random song button does nothing**: no songs have a `youtube_id` yet — run `scripts/verify.py` first.
